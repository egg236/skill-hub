# skill-hub

Локальный менеджер контекста для AI-assisted разработки через Cursor. Хранит независимые модули из Agent Skills, Cursor Rules и переносимых ролей агентов, а затем подключает выбранный набор к конкретному проекту.

Проект я изначально делал для себя и сейчас активно использую в повседневной разработке.

Сам Skill Hub тоже во многом разрабатывался с помощью AI: я использовал его для генерации кода, рефакторинга и экспериментов с архитектурой.

## Какую проблему решал

Одни и те же скиллы и агентские инструкции часто используются сразу в нескольких репозиториях. Если просто копировать их вручную, со временем версии начинают расходиться, а каждое изменение приходится переносить во все репозитории отдельно.

Ещё сложнее становится, когда отдельным репозиториям нужно чуть другое поведение агентов. В одном проекте при этом может быть несколько десятков агентских файлов, и довольно быстро становится непонятно, где лежит актуальная версия, какие инструкции общие для всех проектов, а какие были изменены только локально.

Так появился Skill Hub - единый каталог независимых версионируемых модулей, которые можно безопасно подключать к проектам в нужном составе. Также в Skill Hub есть GUI для управления модулями и встроенная генерация скилов через Cursor CLI.

## Как работает подключение

1. Модули хранятся в `modules/` и не действуют на сам хаб автоматически.
2. В GUI можно выбрать полный итоговый набор для проекта.
3. Skill Hub строит план изменений и показывает предпросмотр.
4. После подтверждения файлы копируются в проект, а их версии и хеши записываются в lock-файл.

| Содержимое модуля | Путь в проекте |
| --- | --- |
| `skills/<name>/` | `.agents/skills/<name>/` |
| `rules/*.mdc` | `.cursor/rules/skill-hub/<module-id>/` |
| `agents/*.md` | `.agents/skill-hub/<module-id>/agents/` |
| ссылки на подключённые инструкции | управляемый блок в `AGENTS.md` |
| состояние установки | `.agents/skill-hub.lock.json` |

Повторное применение того же набора ничего не переписывает. При локальном изменении управляемого файла, конфликте путей или повреждении блока в `AGENTS.md` операция прерывается.

## Демо-каталог

| Модуль | Назначение |
| --- | --- |
| `git-workflow` | Git-процесс |
| `go-ddd` | правила, skill и роль для Go-сервисов с DDD |
| `skill-authoring` | создание переносимых skills |
| `project-init` | минимальная инициализация проекта |

В репозитории также есть presets `minimal`, `autonomous` и `product`.

## Запуск

Требуется Node.js 18+. Установка npm-пакетов не нужна.

```bash
git clone https://github.com/egg236/skill-hub.git
cd skill-hub
node scripts/gui.mjs
```

GUI будет доступен по адресу `http://127.0.0.1:4317`. Другой порт:

```bash
node scripts/gui.mjs --port 4318
```

Системное окно выбора файлов и папок поддерживается в Windows. В других ОС абсолютный путь можно вставить вручную.

## Формат модуля

```text
modules/<group>/<module-id>/
├── module.json
├── rules/
│   └── *.mdc
├── skills/
│   └── <skill-name>/
│       ├── SKILL.md
│       └── ...resources
└── agents/
    └── *.md
```

Версия модуля задаётся в module.json:
```json
{
  "schema": 1,
  "id": "my-module",
  "version": "1.0.0",
  "description": "What this module adds"
}
```

Для взаимоисключающих вариантов добавляется общее поле `family`. Идентификаторы модулей и skills используют `lowercase-kebab-case`.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `gui/` | интерфейс |
| `scripts/` | скрипты для работы каталога |
| `modules/` | текущие версии модулей |
| `releases/` | неизменяемые снимки опубликованных версий |
| `presets/` | именованные наборы модулей |

Стек: Node.js, vanilla HTML/CSS/JavaScript, JSON и встроенный `node:test`.
