# skill-hub

Каталог независимых модулей для ИИ: rules, skills и роли агентов. Подключай в проект только выбранные возможности и один вариант каждой политики.

## Как пользоваться

Открой хаб вместе с целевым проектом и попроси ИИ, например:

- «Подключи Git с подтверждением PR и reviewer в этот проект».
- «Замени Git-вариант на auto-pr, остальные модули сохрани».
- «Отключи модуль X».
- «Создай скилл для проверки SQL-миграций».
- «Инициализируй новый проект с минимальным набором».

В самом хабе доступны служебные скиллы: hub-modules, hub-create-skill, hub-init-project .

Демо-модули в каталоге: `go-ddd` (engineering) и два варианта Git family `git-confirm-pr` / `git-auto-pr` (workflow). Пресеты `minimal` / `product` / `autonomous` по умолчанию подключают `git-confirm-pr`; вариант можно заменить на `git-auto-pr`.
Каталог modules сам по себе не включает содержащиеся в нём правила.

## Локальный GUI

Запусти из корня хаба:

```powershell
node scripts/gui.mjs
```

Открой http://127.0.0.1:4317. Остановка — Ctrl+C. Другой порт: `node scripts/gui.mjs --port 4318`.
Нужен Node.js 18+; управление модулями работает без npm install и внешних сервисов, сервер слушает только 127.0.0.1. Генерация черновиков обращается к Cursor через установленный Agent CLI.

- **Модули:** поиск по названию, описанию и скиллам; просмотр групп и вариантов family; создание, редактирование описания, правил, ролей и текстовых ресурсов, добавление и удаление файлов, удаление модуля. ID остаётся стабильным.
- **Скиллы:** создание и редактирование SKILL.md и текстовых ресурсов в дереве файлов, импорт существующей папки со всеми ресурсами, удаление. Имя импортируемой папки должно совпадать с name в SKILL.md. Лимит импорта — 20 МБ и 2000 файлов.
- **Проекты:** регистрация существующей папки через системное окно выбора, изменение названия или пути, просмотр установленных модулей, существующих скиллов, правил, ролей и локальных правок, выбор полного набора и применение после предпросмотра. Выбор другого варианта family заменяет предыдущий. Preset заменяет выбранный набор.
- **Обновление:** изменение модуля или скилла создаёт новую patch-версию с сохранением предыдущей в истории. Сохранение без изменений не создаёт версию. Чтобы обновить проект, примени его набор модулей.

Удалённые модули и скиллы перемещаются в `.skill-hub/trash/<timestamp-uuid>/modules/...`. Для восстановления перенеси папку обратно в её исходный путь под modules, если он свободен, и запусти validate. Удаление всего модуля блокируется, если его ID ещё указан в preset; сначала поправь соответствующий список в presets. Последний скилл, составляющий всё содержимое модуля, удаляется вместе с модулем.
Копии в проектах остаются до следующего применения. Если модуль удалён из каталога, GUI показывает его среди установленных и позволяет снять выбор для отключения.

В Windows кнопки «Выбрать папку…» и «Выбрать SKILL.md…» открывают системные окна. Выбор папки поддерживает навигацию Проводника и адресную строку; при выборе SKILL.md импортируется вся его папка с ресурсами. Отмена сохраняет текущие поля формы. Окно выбора выводится поверх браузера и доступно через панель задач. Кнопка «Отменить выбор» в вебке и закрытие формы закрывают незавершённый выбор; новый запрос заменяет старое окно. Если окно не появилось за 20 секунд, попытка завершается с возможностью повторить; общий предел ожидания — 5 минут. Для других ОС пока доступен ввод пути вручную.

В проекте раздел «Инструкции на диске» показывает три сворачиваемые группы: скиллы, правила и роли. Скиллы находятся в `.agents/skills`, `.cursor/skills`, `.claude/skills`; правила — в папках `rules` внутри `.cursor`, `.agents`, `.claude`, а также в корневых AGENTS.md, CLAUDE.md и .cursorrules. Роли читаются из `.agents/agents`, `.agents/roles`, `.cursor/agents`, `.cursor/roles`, `.claude/agents`, `agents`, `roles` и установленного каталога `.agents/skill-hub`. Для просмотра и редактирования старых инструкций не нужны module.json или корректный YAML. Кнопка редактирования открывает текст и ресурсы в дереве файлов; двоичные файлы сохраняются без изменений. Ссылки/junction не обходятся автоматически.

Кнопка **«Превратить в проектные модули»** позволяет выбрать до 50 неуправляемых наборов инструкций. Cursor Agent получает их текст, перечень ресурсов и [готовый промпт](scripts/conversion-plan.mjs), доступный для просмотра в окне. Агент предлагает только группировку, ID, группу и описание; хаб проверяет, что каждый выбранный набор включён ровно один раз, и сам переносит исходное содержимое. Хаб сам создаёт и проверяет JSON-снимок с manifest (schema, id, version, description), группой и файлами; отдельный module.json рядом с установленными скиллами не нужен. В предпросмотре доступен свёрнутый manifest JSON; можно изменить метаданные модулей и проверить изменения формата: старые скиллы получают frontmatter, обычные правила — Cursor MDC, а служебный блок skill-hub из корневого AGENTS.md исключается. Готовые MDC сохраняют свои настройки. Ресурсы внутри папок скиллов копируются целиком, включая двоичные файлы; ссылки на внешние файлы нужно проверить отдельно.

После «Создать версии и перенести исходники» появляются модули с тегами вида `Pet проекты · 1.0.0-r1`. Снимки хранятся в `.skill-hub/variants` проекта. Старые инструкции из выбранных наборов убираются из рабочих папок; точные оригиналы, включая двоичные ресурсы, сохраняются в `.skill-hub/migration-backups/<hash>.json` в base64. Список переносимых файлов и архив показаны в предпросмотре. Сохранение версий, резервных копий и перенос выполняются одной операцией с откатом при ошибке; пустые папки исходников затем убираются. Корневой AGENTS.md сохраняется.

После создания открывается шаг «Завершить преобразование · подключение». Пока модуль не подключён, его рабочие файлы не установлены; кнопка «Подключить позже» оставляет только снимок и резервный архив. JSON-снимки не являются файлами SKILL.md или Cursor rules в каталогах автоматического обнаружения. Агент с доступом к репозиторию может прочитать их по запросу; это хранение данных, а не изоляция доступа.

Для ранее созданных версий доступна кнопка «Подключить проектные модули…» в секции «Уникальные проектные», а отдельный модуль можно подключить из его настроек. Эта операция сохраняет точные версии, закрепление и состав уже подключённых модулей. Несохранённые галочки не применяются этим шагом. Если исходники остались от старого преобразования, хаб проверяет их содержимое и замену в снимке, архивирует их и устанавливает рабочие файлы в стандартные пути. Изменённые исходники и наборы без полной замены автоматически не убираются. Для уже подключённых модулей в разделе инструкций доступна кнопка «Убрать старые исходники подключённых модулей…». Подключение и очистка повторно проверяют предпросмотр перед записью.

При переносе хаб обновляет в пользовательской части AGENTS.md точные ссылки на перенесённые файлы, показывает отдельное сравнение и сохраняет резервную копию AGENTS.md. Остальной пользовательский текст сохраняется. Служебный блок продолжает отражать подключённые модули; само его обновление не считается изменением исходных пользовательских инструкций. Ссылки из других документов и ресурсы вне выбранных наборов нужно проверить отдельно.

После подтверждения подключения модули переходят в «Подключённые». При отключении рабочие файлы удаляются, а версии и резервные архивы остаются. Кнопка «Перенести в хаб» создаёт общую версию с обычным тегом, например `1.0.0`. Если исходники изменились после подготовки, преобразование нужно подготовить заново.

Сохранение подключённого скилла, правила или роли сразу записывает правки в проект и создаёт закреплённую версию его модуля с меткой репозитория. Правки других скиллов, правил и модулей автоматически не принимаются под управление. Для старых инструкций сохраняется исходный формат, а копии до и после правки записываются в `.skill-hub/skill-history/<идентификатор-пути>/<номер>.json` проекта; содержимое файлов в снимке — base64. Просмотр этой истории через GUI пока не предусмотрен. При редактировании корневого AGENTS.md служебный блок skill-hub защищён от изменения.

Список модулей проекта разделён на «Модули из хаба» и «Уникальные проектные». Общий модуль с локальной настроенной версией остаётся в первой секции; во второй находятся ID, которых нет в общем каталоге. В каждой секции отдельно показаны подключённые и неподключённые модули по текущему lock проекта. Галочки задают следующий набор и не меняют статус подключения до применения. После переноса уникального модуля в хаб он переходит в первую секцию.

Группы каталога, модулей проекта, скиллов и папки дерева файлов можно сворачивать. Состояние сохраняется в localStorage этого браузера отдельно для каждого проекта и редактора, в том числе после перезагрузки страницы.

GUI использует те же проверки и откат установки, что CLI. Предпросмотр проверяется повторно перед записью: при изменениях проекта или выбранных модулей его нужно обновить.
Не запускай несколько серверов GUI или одновременные изменения CLI/GUI для одного хаба или проекта.

## Версии и варианты репозиториев

На карточках каталога номера версий скрыты. История раскрывается внутри модуля; в проекте источник и версия выбираются в строке «Версия и настройки».

- `Хаб · актуальная версия` — значение по умолчанию для нового подключения; получает текущий модуль при явном применении набора.
- `Хаб · 1.0.0` — закреплённая версия. Следующие обновления проекта сохраняют её, пока ты не выберешь другую или актуальную.
- `my-repo · 1.0.0-r1` — самостоятельная версия для зарегистрированного репозитория. Метка состоит из названия проекта и версии. Такие версии также закреплены.

Общие снимки хранятся в `releases/<id>/<version>.json` и предназначены для Git хаба. Снимок содержит manifest и все файлы модуля, включая двоичные ресурсы. Сохранённый номер версии нельзя перезаписать другим содержимым.
Каталог `modules/` содержит текущую редактируемую версию. История начинает заполняться с этого обновления: при изменении модуля сохраняются его предыдущее и новое состояния; при подключении сохраняется используемая общая версия. Ранее утраченные состояния автоматически из Git не извлекаются. При ручных правках каталога увеличивай version перед подключением.

Варианты репозитория хранятся в его `.skill-hub/variants/<id>/<version>-rN.json`, отдельно от хаба. Это переносимые исходники проектных модулей; их можно включать в Git проекта. Удаление записи проекта из реестра и отключение модулей сохраняют эти снимки.
При регистрации проекта, применении модулей и сохранении проектных версий хаб добавляет в `.cursorignore` служебный блок с `.skill-hub/`. Это исключает архивы, историю и выключенные версии из обычного контекста Cursor; существующие пользовательские записи сохраняются. Рабочие `.agents/skills` и `.cursor/rules` этим блоком не исключаются. После отключения модулей исключение остаётся для сохранённой истории. Это не запрет чтения через терминал/MCP и не отключение текста в корневом AGENTS.md. Глобальный Git ignore настраивается отдельно и автоматически другими установками хаба не меняется.
В проект устанавливаются скиллы в `.agents/skills`, роли в `.agents/skill-hub/<id>/agents`, Cursor rules в `.cursor/rules/skill-hub/<id>`. Lock хранит источник и закреплённую версию.

Рабочий цикл:

1. В разделе проекта выбери «Модуль для репозитория» или «Редактировать для проекта» у существующего модуля.
2. Сохрани проектную версию и примени её через предпросмотр.
3. Если файлы были изменены прямо в репозитории, выбери «Правки репозитория → версия». Проверь добавленные, изменённые и удалённые файлы. Сохранение принимает только просмотренные файлы этого модуля под управление новой проектной версии; остальные локальные правки остаются защищены.
4. «Перенести версию в хаб» покажет сравнение с текущим общим модулем. Перенос создаёт новую общую версию с содержимым выбранной проектной версии и меткой происхождения. При изменении хаба после предпросмотра требуется новое сравнение.
5. Другие проекты получают эту общую версию при отдельном обновлении. Закреплённые и проектные версии сохраняются.

Перенос в хаб заменяет содержимое модуля новой версией целиком; автоматического слияния двух наборов правок нет. Перед переносом проверь сравнение. Для проекта с несколькими изменёнными модулями сохрани каждый через его действие захвата правок.

В CLI можно закрепить версию так:

```powershell
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" review@1.0.0 git-confirm-pr
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" review@latest git-confirm-pr
```

Обычный ID сохраняет существующее закрепление, включая проектную версию. `id@latest` явно возвращает модуль к актуальной общей версии хаба. Preset в GUI заменяет набор актуальными общими версиями.

## Общие файлы и выбираемые наборы

В редакторе модуля раскрой «Обязательные файлы и варианты». Можно создать группы выбора, задать названия вариантов, включённые файлы/папки и значения по умолчанию. Группа допускает один либо несколько вариантов. Файлы вне вариантов подключаются всегда; family по-прежнему выбирает один модуль целиком.

В проекте у выбранного модуля появляется «Состав подключения». Отметь нужные наборы и примени изменения через предпросмотр. Выбор хранится в lock проекта и сохраняется при обновлении; локально изменённые файлы не удаляются автоматически при снятии выбора.

В `ui-direction@1.0.2` общие инструкции, ограничения, тексты и шаблоны подключаются всегда. Четыре mood-набора — ops-dense, warm-editorial, dark-tool, commerce-clean — выбираются отдельно; при новом подключении все выключены. Скилл работает и без mood. При обновлении старой установки ранее подключённые moods сохраняются. Старые закреплённые версии сохраняют прежний состав.

В CLI выбор задаётся флагом `--choose`, который можно повторять для разных групп:

```powershell
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" ui-direction --choose ui-direction:moods=dark-tool,warm-editorial --dry-run
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" ui-direction --choose ui-direction:moods=
```

Пустое значение оставляет общие файлы; без флага сохраняется выбор проекта, а для нового подключения используются defaults. Как и обычный apply, команда принимает полный набор модулей.

Снимки версий всегда содержат полный модуль со всеми наборами. Редактирование проекта и перенос в хаб сохраняют также ресурсы, которые в проект не подключались.

## Агент в редакторе файлов

В карточке модуля доступны скиллы, правила Cursor и роли: кнопки открывают выбранный файл в редакторе. Агент работает с SKILL.md, правилами, ролями и текстовыми ресурсами. Раскрой «Попросить агента изменить файл», опиши задачу и нажми «Создать черновик». Готовый текст отображается отдельно: сначала вставь его в редактор, затем сохрани новую версию.
Закрытие редактора или кнопка «Остановить» отменяет текущую задачу. Если за время работы агента ты изменил текст, черновик не затирает эти изменения.

Инструкции агента требуют минимальных правок в пределах выбранного файла: сохранять не относящиеся к задаче фрагменты, форматирование и метаданные; не делать попутный рефакторинг или дополнительные «улучшения». Задача и исходный текст передаются раздельно в JSON, содержимое файла обозначается как материал для редактирования. Ответ с дополнительными файлами или полями отклоняется; создание дизайна ограничено тремя файлами одного набора. Перед вставкой GUI показывает сравнение «было / стало». Сохранение выполняется отдельно кнопкой пользователя; смысловую точность правок можно проверить по сравнению.

Используется установленный и авторизованный **Cursor Agent CLI**. Команда запуска: `agent --print --mode ask --trust --output-format json --workspace <временная-папка>`; задача и текст выбранного файла передаются через stdin. Режим `ask` предназначен для чтения и ответов; агент возвращает черновик, а запись версии выполняет GUI. `--trust` относится только к новой временной рабочей папке, созданной хабом, и убирает интерактивный вопрос Workspace Trust. В ней хаб создаёт AGENTS.md с границами задачи и `.cursor/cli.json` с deny для Shell, Write, Read, WebFetch и MCP; глобальные настройки Cursor не изменяются. Запуск идёт без shell, `--force` и `--yolo`. Формат локальных разрешений описан в [документации Cursor](https://prod.cursor.com/docs/cli/reference/permissions). Совместимость параметров проверена с установленным CLI 2026.07.23-e383d2b; протокол успешного ответа, ошибок и отмены проверяется локальным тестовым процессом. Подробнее: [Cursor CLI](https://prod.cursor.com/docs/cli/headless), [формат ответа](https://docs.cursor.com/en/cli/reference/output-format).

CLI должен быть установлен отдельно от редактора Cursor; для входа выполни `agent login`. GUI находит `cursor-agent`/`agent` в PATH, а в Windows также стандартную установку Cursor Agent с её bundled runtime. Если путь нестандартный, укажи абсолютный путь к CLI или его `index.js` в переменной `BRAIN_HUB_CURSOR_AGENT` перед запуском GUI. Одновременно выполняется одна задача; предельное время — 5 минут. Ключи и credentials в хабе не хранятся.

## Создать дизайн через агента

В карточке `ui-direction` нажми «Создать дизайн через агента», укажи ID, название, продукт и желаемое направление. Cursor Agent использует служебный скилл [.agents/skills//SKILL.md](.agents/skills//SKILL.md) и общие ограничения модуля. Результат — mood-набор: DESIGN.md, COPY.md и tokens.css.

Сначала создаётся черновик. Переключайся между файлами, проверь и отредактируй их, затем нажми «Сохранить дизайн в новой версии». GUI добавит новую папку в moods и вариант в choices; прежние наборы и defaults сохраняются. Новый дизайн выбирается отдельно в составе подключения проекта. Если модуль изменился за время генерации, сохранение остановится: нужно открыть актуальную версию. Ответы агента не исполняются и сами не записывают файлы.

Начиная с `ui-direction@1.0.3`, инструкции учитывают пользовательские moods по доступным папкам. Скилл `` также доступен агенту при работе непосредственно в репозитории хаба.

## Реестр проектов

`projects.local.json` в корне хаба хранит локальный список. GUI создаёт файл при первой регистрации; для ручного начала есть `projects.example.json`.

```json
{
  "schema": 1,
  "projects": [
    {
      "id": "my-app",
      "name": "Мой проект",
      "path": "`{{LOCAL_PROJECT}}`"
    }
  ]
}
```

ID записи стабилен; GUI генерирует его автоматически. Путь абсолютный, папка должна существовать вне хаба. Реестр и корзина исключены из Git и не копируются в модули или проекты. Удаление записи из реестра сохраняет папку проекта и подключённые модули. Установка через CLI не требует регистрации.

## Структура

```text
skill-hub/
  modules/
    workflow/
      git-workflow/       варианты git-confirm-pr и git-auto-pr
      documentation/      варианты docs-confirm и docs-auto
      worktrees/
      task-workflow/
    engineering/          backend, frontend, devops, environment, review, qa
    product/              analysis, product-bootstrap, ui-direction
    integrations/         notion
    authoring/            skill-authoring, project-init
  releases/<id>/          неизменяемые общие версии для Git
  presets/                явные списки модулей
  .agents/skills/          служебные скиллы хаба
  scripts/hub.mjs          установка, проверка и отключение
  scripts/gui.mjs          локальный HTTP-сервер
  scripts/gui-store.mjs    операции каталога и реестра
  scripts/module-history.mjs  снимки, версии и варианты репозиториев
  scripts/agent-jobs.mjs    запуск агента для черновиков
  gui/                    интерфейс
  projects.example.json   пустой пример реестра
  projects.local.json     локальный реестр, вне Git
  .skill-hub/trash/        локальная корзина, вне Git
```

Каждый модуль работает отдельно. Нет обязательного core, скрытых requires, наследования presets и автоматического подключения соседних модулей.
Группы организуют каталог по назначению. Варианты одной family находятся в общей папке; группы не добавляют зависимости и ничего не подключают автоматически.
Внутри модуля остаются module.json и необязательные rules/, skills/<name>/, agents/. Ресурсы скилла лежат внутри его папки.
Helper находит модули рекурсивно; ID не зависит от группы и сохраняется в presets и lock. Перенос папки с неизменённым содержимым не требует переустановки в проектах. IDs уникальны во всём каталоге.
Реестр проектов хранится отдельно в корне хаба; remote, Notion URL и credentials остаются настройками целевого проекта и не попадают в модульный каталог.

## Каталог

| Модуль | Что подключает |
|---|---|
| git-confirm-pr | Ветка и PR, подтверждение готового результата перед push/PR |
| git-auto-pr | Commit, push и PR без дополнительного вопроса в delivery-задаче |
| docs-confirm | Подтверждение точного текста документации |
| docs-auto | Нужная документация в составе разрешённой задачи |
| worktrees | Изоляция изменений в linked worktrees |
| review | Reviewer без обязательного трекера и approvals |
| backend / frontend / devops | Отдельные роли реализации |
| environment | Локальный runtime и порты |
| task-workflow | Короткий цикл реализации и проверки |
| analysis | Discovery, артефакты, BA и SA |
| product-bootstrap | Идея, MVP, сценарии и задачи реализации |
| qa | Test-case design и ручное QA |
| ui-direction | Moods, тексты, tokens и шаблоны внутри скилла |
| notion | Явно заданные страницы, задачи и workspace Notion |
| skill-authoring | Самостоятельный create-skill |
| project-init | Самостоятельный init-project |

git-confirm-pr и git-auto-pr занимают одну family git-workflow. docs-confirm и docs-auto занимают family documentation.
Одновременно можно выбрать не более одного варианта family. Ни один вариант не обязателен.
auto-pr относится к публикации PR в рамках задачи; merge и release из него не следуют.

## Подключение

Нужен Node.js 18+; npm install не требуется. Папка проекта уже должна существовать.

```powershell
node scripts/hub.mjs list
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" git-confirm-pr review --dry-run
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" git-confirm-pr review
node scripts/hub.mjs status "`{{LOCAL_PROJECT}}`"
```

apply принимает ПОЛНЫЙ итоговый набор. Модули, которых нет в списке, отключаются; незакреплённые общие модули обновляются из текущего checkout хаба. Закреплённые и проектные версии сохраняются.
Для замены Git-варианта сохрани остальные IDs:

```powershell
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" git-auto-pr review
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" review
node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" --none
```

Presets являются удобными списками: minimal, autonomous, product. Они не включаются по умолчанию.
Пример: node scripts/hub.mjs apply "`{{LOCAL_PROJECT}}`" --preset minimal --dry-run.
Preset и дополнительные IDs объединяются; конфликт family нужно разрешить явно.

В проект копируются только выбранные skills в `.agents/skills`, роли в `.agents/skill-hub/<id>/agents`, а `rules/*.mdc` — в `.cursor/rules/skill-hub/<id>`.
AGENTS.md получает ограниченный маркерами блок ссылок, пользовательский текст сохраняется. Ссылки на MDC служат каталогом: условия применения правил определяются их метаданными Cursor.
.agents/skill-hub.lock.json хранит IDs, версии и хеши управляемых файлов. Не редактируй его вручную.
Повторный apply без изменений ничего не переписывает. --dry-run вообще не создаёт файлы.

Перед записью helper проверяет весь набор. Он отказывает при локальных правках управляемого файла, конфликте с чужим файлом, повреждённых маркерах и symlink/junction внутри управляемых путей.
AGENTS.md должен быть UTF-8; иная кодировка требует явного преобразования, файл автоматически не перекодируется.
При обычной ошибке записи helper восстанавливает уже затронутые файлы. После аварийного завершения процесса проверь status и Git diff; одновременные apply в один проект не поддерживаются.
Удаление затрагивает только учтённые неизменённые файлы. Чужие дополнительные файлы сохраняются; пустые каталоги и пустой lock допустимы.
Для кастомизации правь модуль в хабе или проектный текст вне управляемого блока, затем повторяй apply.

Если одноимённый скилл уже есть на диске, но его нет в lock хаба, обычный apply сообщает «Файл принадлежит проекту». Это возможно после ручного копирования или использования прежней структуры. Даже совпадающий текст сам по себе не делает файл управляемым.
GUI открывает сравнение и предлагает «Подключить, сохранив файлы проекта». Это явное подключение создаёт закреплённую версию репозитория: существующие файлы скилла и его дополнительные ресурсы сохраняются, недостающие файлы выбранного модуля добавляются. Предпросмотр показывает отличия и весь план установки; после изменения файлов его нужно открыть заново. Снимок версии и установка записываются с общим откатом. Остальные скиллы проекта не принимаются под управление автоматически.

## Совместимость и ручное подключение

Основная среда — Cursor: [проектные skills](https://prod.cursor.com/docs/skills), [правила MDC и AGENTS.md](https://prod.cursor.com/docs/rules). Правила текущего каталога используют `.mdc` с YAML frontmatter. `alwaysApply: true` включает правило постоянно; `false` позволяет использовать globs, описание или ручное подключение. GUI создаёт правило с `alwaysApply: true`; метаданные можно изменить в редакторе модуля.

Переход на MDC сохранён отдельными patch-версиями. Исторические версии с `rules/*.md` сохраняют прежнее содержимое и расположение `.agents/skill-hub/<id>/rules`. При выборе актуальной версии helper заменяет неизменённые старые управляемые правила на MDC. Локальные правки сначала сохрани через «Правки репозитория → версия». При переносе такой старой версии в хаб её правила преобразуются в MDC; проектная копия сохраняется. Чужие правила в `.cursor/rules` сохраняются.

Роли agents/*.md являются переносимыми инструкциями. Helper не регистрирует нативных subagents в настройках конкретной IDE; основной агент может принять роль или передать её доступному исполнителю.
Для другой среды используй её механизм подключения файлов и скиллов. Для Cloud включи установленный контекст в Git целевого проекта.

Без Node можно скопировать выбранный модуль вручную: `skills` в `.agents/skills`, `rules/*.mdc` в `.cursor/rules/skill-hub/<id>`, роли в отдельную папку проекта и ссылки на них в AGENTS.md.
Проверь family и совпадения имён, сохрани список скопированных файлов. При отключении убери ссылки и только эти неизменённые файлы.
Ручная установка не создаёт lock helper: не смешивай два способа без явного разбора существующих файлов.

## Добавить модуль

Создай modules/<group>/<id>/module.json (или воспользуйся GUI):

```json
{
  "schema": 1,
  "id": "my-module",
  "version": "1.0.0",
  "description": "Назначение модуля"
}
```

Для взаимоисключающих вариантов добавь одинаковую family и размести их в modules/<group>/<family>/<id>. Все варианты family должны иметь одну родительскую папку; валидатор проверяет это. Family — только запрет совместного выбора, без наследования.
Допустимы только поля schema, id, version, description, family, choices. ID и имена skills используют lowercase-kebab-case.
Добавь нужные rules/*.mdc с YAML frontmatter и boolean-полем alwaysApply, skills/<name>/SKILL.md с name/description и/или agents/*.md. Ресурсы скилла размещай внутри него.
Обязательные ссылки не выходят за пределы модуля. Опциональные возможности имеют рабочий путь без соседнего модуля.
При ручном изменении опубликованного содержания обновляй version. GUI увеличивает её автоматически и сохраняет снимки. Старый проект обновится только при явном apply; закреплённая версия меняется только по явному выбору.

Необязательное поле `choices` содержит группы вида:

```json
{
  "id": "moods",
  "title": "UI moods",
  "multiple": true,
  "default": [],
  "options": [
    {
      "id": "dark-tool",
      "title": "Dark tool",
      "paths": ["skills/pet-ui-direction/assets/design/moods/dark-tool/"]
    }
  ]
}
```

`paths` — точные пути внутри модуля; завершающий `/` обозначает всю папку. Маски и выход за пределы модуля запрещены. Путь должен существовать, файл не может входить в разные варианты, у модуля остаются общие файлы. Если весь скилл необязателен, SKILL.md и все его ресурсы должны принадлежать одному варианту. Общие инструкции должны работать без дополнительных наборов.

Проверка каталога: node scripts/hub.mjs validate. Проверки установки: node --test tests/hub.test.mjs. Проверки GUI API, реестра, импорта, удаления и предпросмотра: node --test tests/gui.test.mjs. Проверки версий, вариантов, переноса и протокола агента: node --test tests/versions.test.mjs. Проверки просмотра старых скиллов, выбора пути и подключения существующих файлов: node --test tests/project-import.test.mjs. Проверки выбираемых наборов, редактирования файлов проекта и памяти свёрнутых групп: node --test tests/choices.test.mjs. Проверки появления окна выбора, отмены, повторного открытия и отключения клиента: node --test tests/path-picker.test.mjs. Проверки агента для правил/ролей и создания дизайнов: node --test tests/design-agent.test.mjs. Проверки trust, локальных разрешений и границ ответа агента: node --test tests/agent-scope.test.mjs.
Исходная структура сохранена в истории Git до переработки. Другие проекты автоматически не мигрируются.
